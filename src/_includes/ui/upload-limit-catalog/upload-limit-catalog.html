{# 上傳大小界線的**唯一正本**：單檔 50 MiB、單次送出總量 200 MiB，在這裡宣告一次，各消費點共用。 **為什麼非目錄不可**（GUIDELINE §2 為 `*-catalog` 放寬 `{% from … import %}` 的那條）：這顆數字有 兩個消費點——`ui/upload-box`（`.upload-desc` 的可見文字 ＋ `data-max-mb` 那顆選檔當下的夾檔判準） 與 `ui/upload-card`（三張卡的 `.upload-desc`）——而 `{% include %}` 表達不出「共用一份資料」 （獨立 scope，子檔 `{% set %}` 的變數回不到父頁），`_data/` 又被 §2 明文禁止。 各烤一份不是假想的風險：只要讓每張卡自己寫一個數字（Excel 10MB、其餘 30MB 這種）， 那幾個手抄值裡就只有一個可能是對的——所有上傳路徑共用的是**同一條**上限， 沒有「某個格式專用」的版本。 而這種錯**在畫面上完全看不出來**：每張卡各自看起來都很合理，要並排比對才會發現它們不一致。 **單位是 MiB**：`52428800` ＝ 50 × 1024 × 1024，故 `upload-box.js` 換算用 1024 不是 1000。 **`batchMaxMb` 是同一組界線的第二顆**：單檔上限擋不住「一次送一百個 49MB」，所以另有一道 總量閘。它只在**開了多選**的那條路上撞得到（單選一次只送得出一個檔，總量恆等於單檔大小）， 所以只有 `uploadMultiple` 的實例畫得出它——但界線本身仍然只有一份，不因頁而異。 **兩顆放在同一份目錄**的理由與上面那一段相同：同一組界線分了家，改其中一顆時另一顆不會有人動， 而「單檔 50MB、一次最多 60MB」這種說不通的組合在畫面上看起來完全正常。 目錄只放跨消費點都相同的欄位（§2）：格式清單（xlsx／pdf／docx）因頁而異，留在各自的 `uploadDescPrefixKey`／`card.descKey`，不進這裡。 #} {% set uploadLimitCatalog = { maxMb: 50, batchMaxMb: 200 } %}
