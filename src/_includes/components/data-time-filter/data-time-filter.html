{# 「資料時間篩選」整列（近24小時／上週／上個月／時間區間＋起訖欄）。 5-3 統計模組與 5-4 覆蓋缺口逐字相同，§3-3「同一段版面出現在 2 頁以上就抽成元件」。 抽成元件的理由不只是省行數：手抄兩份時分岔會落在 role 這種看不出來的屬性上。 兄弟列（查詢資料類型）是純 radio，只有 `radiogroup` 對，`group` 讀不出「三選一」 （見 data-type-filter）。 **但這一列不是** `radiogroup`：`field-with-input-group` 的構造讓它必然含兩個文字欄 （起訖時間），`radiogroup` 的 owned element 只能是 radio，報讀器會把那兩格念成單選成員。 故這一列維持 `role="group"`。 參數（使用頁在 include 前 set，見 §3-2/§6）： timeFilterName —— radio 的 name（同頁多組要不同：5-3 是 data-time、5-4 是 gap-time） timeFilterLabelId —— 群組標題的 id（供 aria-labelledby 指到；同頁唯一） timeFilterChecked —— 預設選中哪一顆：last24h / lastWeek / lastMonth / range（不給＝一顆都不選）。 這是**參數名**，不是送出去的值：`value` 是這一組選項的識別字 （daily／weekly／monthly／custom），在這裡定義一次就是正本。 四顆都帶 `data-filter-reset`： 清除鈕**不由 type 推導**哪些是篩選參數，沒宣告的 radio 它一顆都不碰 （見 `ui/filter-fields` 的 js），於是按了清除時間篩選會留在原地。 timeFilterRangeHintId —— 區間上限那句常駐說明的 id（同頁唯一；起訖兩欄 aria-describedby 指它） **365 這個數字寫在元件裡、不開成參數**（§6 (a) 全站不變的結構性設定）：兩個消費頁吃的是 同一組界線，而且兩條界線同一個數字——開始時間不得早於 365 天前、 區間不得超過 365 天。哪一天有頁面要不同的界線，才照 §6 開成參數。 為什麼非有這一句不可（§4-2）：兩頁「查詢」鈕的 `data-toast` 把 365 烤進譯文，而屬性型譯文 那條例外**要求同頁另有一處常駐可見的節點承載同一個數字**——沒有它，改了上限只會讓譯文 靜默過期。故走正典寫法：前綴 key ＋ 不翻的 `` 數字節點 ＋ 後綴 key，並依 §3-2 「值域寫在填之前」擺在起訖欄旁邊、而不是等按下查詢才由 toast 說。 起訖欄是日期選擇器的掛點（`.start-date`／`.end-date`），切版不引 vendor、 只保留 class 與 disabled 初始態；`.time` 是 form-control 的日曆圖示變體（`.field:has(> .form-control.time)::after`）， 全站的日期輸入欄一律帶它——4-1 的同型欄位也是這一顆，三處要一致。 `.field-with-input-group` / `.field-with-input` / `.with-input` 是**業務掛點／轉換契約** （選了哪顆 radio 就解除它附屬輸入框的 disabled），不是無主 class—— 那個 `disabled` 初始態的意義就是「還沒選時間區間」。行為由 `ui/field-with-input` 當場做（§5 ④）。 #}
至

時間區間最長 365 天，開始時間也不得早於 365 天前；超出的範圍送出會被退回。
