{# 匯入精靈「欄位對應」那一步的左右兩欄盒（1-1-4）：左欄逐槽問「把哪一個來源欄對到這個槽」， 右欄同步顯示「對完長什麼樣」的預覽。 兩欄的欄位清單都由同一份槽目錄跑 `for` 靜態展開——不靠執行期 js 生 DOM，行數、順序、欄名 兩欄才必然一致（一邊多一列、另一邊沒有，使用者就對不起來了）。 左欄「select.multiSelect」重用 ui/multi-select 既有 class 命名（由已登記的 ui/multi-select/multi-select.js 於 DOMContentLoaded 增強成 tag 多選 UI）； 左右兩欄的 form-group/label/field 結構沿用 ui/form-control 既有寫法。 `.field-<槽鍵>`／`.preview-<槽鍵>` 兩族是**逐槽定位左右欄的業務掛點**，全站零樣式、零本 repo js——槽鍵集合的 唯一正本是 `ui/field-slot-catalog`（22 槽，對回 product 的 `SLOTS`）。 測試那一份白名單（`tests/guideline.test.mjs` 由 catalog 推導出這兩族）逐字指著**這一段**當契約 正本，所以這裡不能不寫（§4「痕跡要成對：只住在測試裡的豁免，讀元件的人看不到」）。 `.date-error` 是**日期欄錯誤訊息的業務掛點**，全站零樣式、零 js——切版改由 `.form-group:has(.error)` 揭示， 掛點原樣保留（§5 轉換契約，不是無主 class；沒有這一句它長得就像 §4 死法②）。 本元件不自帶任何槽清單，三個變數全部由使用頁供給（§3-2/§6）——**其中一個不是 `{% set %}`， 是 `import`**，而缺了那一行的失敗方式與缺一個 `set` 完全相同：不報錯、只是整個迴圈跑 0 次， 兩欄一起變成空白。使用頁 include 之前必須有這三行（§1-2：契約要含它自己需要的定義行）： {% from "ui/field-slot-catalog/field-slot-catalog.html" import fieldSlotCatalog %} {% set columnOptions = [ { value: "0", label: "客服問題" }, { value: "1", label: "客服回覆" } ] %} {% set fieldExtras = { title: { selected: "0", placeholder: "建議選擇「標題」屬性欄位", placeholderKey: "fieldHint.title", preview: "如何申請入出國許可證" }, date: { placeholder: "YYYY/MM/DD HH:mm:ss || YYYY-MM-DD HH:mm:ss", preview: "2024年12月1日 下午1時", error: true } } %} （`columnOptions` 是每個來源欄一筆、`fieldExtras` 是每個要覆寫的槽一筆；上面各列兩筆同型節點示意， 實際筆數看使用頁。） · `fieldSlotCatalog`（來自 ui/field-slot-catalog 的唯一正本）：逐槽的 `key`／`defaultLabel`／ `productOnly`。本元件對它跑三圈：非 productOnly 的欄位、`msHasProductOnly` 的偵測、 productOnly 的欄位。 · `columnOptions = [{ value, label }]`：來源欄位選項，**全部的槽共用同一份**——來源檔的欄位 是同一組，每顆 select 只是從同一份清單裡各挑各的，不必逐槽再算一次。 · `fieldExtras`：以槽 key 查的差異——`selected`（預選的 option value）／`placeholder` ＋ `placeholderKey`（ui/multi-select 的資料槽，§4-2）／`preview`（右欄預覽值）／ `error`（true 時右欄那格標紅並揭示格式警告）。查不到的 key 就是「沒有差異」，不是錯誤。 #}
