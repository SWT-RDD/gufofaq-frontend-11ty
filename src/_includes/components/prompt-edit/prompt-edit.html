{# 提示詞（收合 / 展開編輯）：收合時只露第一行預覽，展開時換成可編輯的 textarea ＋ 一列工具鈕。 展開/收合（切換 .open、注入編輯 textarea 或首行預覽）是純視覺互動，由 prompt-edit.js 提供； 實際儲存／建新版本等 API 屬業務邏輯，切版不實作（§5）。 參數：promptDefaultOpen（true 時加 data-default-open，開頁即展開）。 **唯一使用者是 5-2 對話設定頁**（AB 測試頁不用這支元件，見 2-2-3 檔頭）； 元件庫展示頁另放一份 `promptDefaultOpen: true` 的示範——沒有那一份， prompt-edit.js 那句 `hasAttribute("data-default-open")` 的「預設展開」初始態全站沒有人看得到 （§5 每個分支都要演得出來）。 #} {# 示範提示詞取領域中性的知識庫助手文案：5-2 的示範資料橫跨好幾個主題（政策、輸出規則、 內建工具），綁定單一領域的提示詞會與同頁其他區塊的示範對不起來（§6 示範自洽）。 #} {# 編輯 textarea 的長度上限：單一提示詞 20000 字，在這裡宣告一次 （同一顆上限也夾住五層系統提示詞；正典寫法見 skill-editor-modal 的 `skillInstructionsInput`）。**一個數字只有一份真相**（§6）：`data-max-len` 給 js 拿去掛到注入的 textarea 上，下面那句可見提示渲染同一顆變數——不是 js 寫死一份、markup 寫死另一份。 那個數字是**資料不是譯文**（§4-2：契約裡有欄位的常數不准寫進 data-i18n 的句子裡）。 提示常駐可見（收合態也在）：§4「帶約束的輔助文字要常駐可見」——只有展開時才出現的話， 使用者是在「已經打完一大段」之後才第一次讀到它。 #} {% set promptEditMaxLen = 20000 %}
提示詞 {# 按鈕文字隨 .open 切換（見 prompt-edit.js）：data-text-* 是繁中原文，data-key-* 是對應的 i18n key。 **後綴是「當下狀態」、值是那一態該顯示的「動作」**（open ⇒「完成編輯」＝按了會收合）—— 本檔是這種狀態式命名的正典，ui/theme-toggle 的 data-*-light／-dark 指到這裡； 後綴是「按下去要做的事」的動作式另有一套，見 ui/reveal-input。 `aria-describedby` 指那句字數上限：編輯用的 textarea 是**展開時才注入**的（見 prompt-edit.js 的 `render()`），所以收合態下那顆 hint 的 id 沒有任何控制項指得到它 ——§4 反向那條逐字說「掛了 id 的輔助文字必須至少有一個控制項指到它」。這顆鈕是本元件 **唯一常駐的控制項**，而且它正是「進去編輯」的入口：把上限講在按下去之前，也才對得上 §3-2「上限寫在做那個決定的控制項旁邊」。展開後注入的 textarea 另外自己再指一次 （同一個 id，§4「同一個欄位在同一頁出現多次時每一處都要有」）。 #}
{# `js-prompt-len-hint` 是本元件 js 的掛點（拿它的 id 去接注入 textarea 的 aria-describedby）： js 走 class 找、不從自己那邊寫死 id 字面（§5：id 是頁面層的東西，正本在這行 markup）。 ⚠️ 這顆 id 是**字面量**，所以本元件目前一頁只能有一份（5-2 一份、元件庫頁一份）—— 要一頁兩份就得把 id 提成參數，上面那顆鈕的 `aria-describedby` 也要跟著吃同一個參數 （兩處是同一個交付單位，只改一邊會留下指不到的 describedby）。 #}

{# 四顆鈕裡有兩顆聽起來都像「存」，而只有一顆真的存得下去——這一句就是在分那件事。 **持久化只有一條路**：「儲存為新版本」那一顆——它逐欄寫回設定檔本體， 內容沒變就不會多開一版。 而它**當場改變線上機器人的回答**——寫的是設定檔本體，不需要再套用一次——所以這件事必須 在畫面上講出來，不能只留在按鈕名字裡（姊妹的 `components/apply-settings-modal` 對同一種 後果有 `modals.applyOverwriteWarning`）。 回復的路要一起講：舊版本留在版本紀錄裡，否則這句警語只嚇人、不給出路。 #}

「暫存編輯」只把目前打的內容留在這個編輯器裡，離開頁面就沒了；要真的生效必須按「儲存為新版本」——那會直接寫進這個設定檔，前台只要用的是這個設定檔，下一題就換成新的提示詞，不必再套用一次。改壞了不要緊：舊版本都留在下面的版本紀錄裡，隨時可以回復。

{# ⚠️ **這一顆不送任何 API，它的字面必須說得出這件事**。 它做的事逐字是 prompt-edit.js 的 `saveFromTextarea()`：把 textarea 的內容寫回 `data-full-text`、**不收合**。`.js-prompt-save` 是具名業務掛點（見 5-2 檔頭的草稿卡契約）， 所以 class 不動。 字面必須是「暫存編輯」而**不能寫成「儲存」**：這個畫面上唯一存得下去的是右邊那一顆 「儲存為新版本」，兩顆鈕都說「存」而只有一顆是真的，接手的人就會照字面把它接上 寫入路徑——鈕上寫著儲存，就必須真的存得下去。那不是讀錯，是字面在說謊。 解法是改字面，**不是替它補一道閘門**：補閘門等於承認它會寫入，而那會讓它與 「儲存為新版本」變成同一顆鈕（持久化只有一條路）。 故：不掛 `data-capability`、不掛 `data-toast`（§5 矩陣②：純本地互動只留 hook）。 #} {# 送 API 的直接動作鈕（`.js-prompt-reset`：去取目前正式提示詞、再寫回編輯器） ⇒ `data-toast` 要列全結果（§5）。 **必須掛 `data-capability`**：它要去讀目前正式的提示詞，而讀這件事本身也要 `settings:read` 這道能力。§4 的判準是「**這個動作要不要一道能力才做得到**」， 不是「會不會改狀態」——唯讀的動作同樣要標。這一格不能留空：空白與「忘了標」在 markup 上 長得一模一樣，看的人分不出哪一種。 #}
