{# 檢索範圍：挑「這次要搜哪些資料集」。3-7 文件檢索的「檢索範圍」鈕開它。 這一顆窗是**無條件開窗**（點了就開，沒有任何前置條件），故觸發鈕掛 `data-open-modal`、 不是 hook class（§5）。 這一窗的清單與值（在這裡宣告一次，就是正本）： · 清單來源＝**本租戶的**資料集，不是全平台的索引清單——把跨租戶的清單端到這一窗， 等於把別的租戶的索引名端到瀏覽器上。 · 勾起來的那幾筆送出去的是 **dataset id**，隨下一次的文件檢索一起送；索引名在伺服器端翻譯， 而那一步同時就是擁有權檢查（別的租戶的 id ⇒ 查不到）。 **值是 id 不是索引名**，這不是換個欄位那麼簡單：索引名是內部識別，讓瀏覽器持有它 等於給前端一個猜別人索引名的起點。 · **這一窗自己不打任何 API**：勾選的範圍是下一次檢索的查詢條件、不是使用者設定——沒有 「把這個帳號要搜哪些資料集存起來」這回事，所以確認鈕沒有成功／失敗可列，也就沒有 `data-toast` （§5 矩陣②：值載體只掛 hook、不列 toast——**不是④**，④ 那一族連 hook 都不掛， 而這一顆是 React 要認的交付點）。 **這一窗刻意沒有的東西**（§4：不做的要寫明理由，否則下一個人分不出「不能」與「還沒」）： · **沒有第二欄「自訂資料集」清單**：資料集之上沒有再一層的容器概念 ⇒ 兩欄併成一份清單。 · **每一列沒有「優先度」下拉**：檢索請求不收這個欄位，多帶一顆會整個請求被拒 ⇒ 送出即失敗。 **畫得出來卻送不出去的旋鈕在這條路上不是「還沒接」，是送出即失敗。** · **沒有「空＝全部」這一態**：至少要送一個 dataset id，空清單會被拒。 「檢索全部」＝**逐一送出每一個 id**，不是送一份空清單（「全選」是把列出來的那幾筆一次 勾起來的捷徑，射程見下面那一段）。 空清單如果被當成「不加任何條件」，那個「全部」就是**全平台**而不是本租戶； 即使中間有一層把它翻譯成「本租戶全部」，那個形狀還留在契約上——少翻一次就是跨租戶檢索， 而回應看起來完全正常。 所以**這一窗要收掉那個值**，不是靠別人補救。 · **一筆都沒勾時彈 warning、留在窗裡**（`search-scope-modal.js`），**不是把確認鈕 `disabled`**： 「沒選任何一筆」的理由要說得出口，而合規的 `disabled` 只有「進行中」與「type-to-confirm 尚未解鎖」兩種（REACT-CONVERSION §⑥）。同一個前提全站已有兩處正典，兩處都是 warning 分支 ——`select-dataset-modal`（js 彈 warning、留在窗裡）與 `config-copy-modal`（`data-toast` 的 「請至少勾選一個複製項目」）——這一窗是第三處，不另立第三種寫法。 ⚠️ **不可以退成 `if (!checked) return;`**：那是零訊號，讀起來與「這顆鈕壞了」逐字相同。 確認鈕因此**不掛 `.btn-close-modals`**：關不關窗取決於勾了沒有，那不是宣告式的 （同 `select-dataset-modal` 的 `.js-confirm-dataset`）。 · **`#searchScopeEmptyHint` 是這一窗的規則說明，不是那顆 warning 的替身**：它常駐可見在清單 下方、由清單 `aria-describedby` 指過去，講的是「至少一個」與「全選只勾得到列出來的那幾筆」 ——兩件按下去之前就該知道的事。**清單空的時候整段不渲染**（連同那個 `aria-describedby`）： 那一態畫面上是「這個租戶還沒有資料集可以選」，叫人去勾一個不存在的東西是假話， 而真正的下一步（去建一個資料集）那一句自己就說了。
