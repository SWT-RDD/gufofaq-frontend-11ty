三個動作的破壞程度差很多：「刪除逾時資料」清掉那些帳號的資料集與索引、帳號本身留著；「刪除逾時帳號」連帳號、使用者一起永久刪除，只留稽核日誌；「凍結逾時帳號」只是暫時停用，解凍時剩餘天數會原封補回來——三者之中只有它有回頭路。

{# ── type-to-confirm 片語（round45 裁決）──────────────────────────────────────── **片語是「值」，不是 chrome，所以它永遠不掛 `data-i18n`。** 原本 label 與 placeholder 各掛一顆 key，繁中要打「刪除」、英文要打 `DELETE`——**同一道閘在兩個語系要求不同的輸入**，而 React 端 比對的只會是其中一份，另一個語系的使用者照著畫面打就是解不開。 正典有兩處：同站 manage-tenant-modal 的 type-to-confirm 打的是**租戶名稱**（一個值，兩個語系 都打同一串），product 的 `declare_filter_slots` 用 `_FILTER_SLOTS_CONFIRM_PHRASE = "REBUILD-ALL"` （逐字比對的固定字串，並在 400 訊息裡把片語本身回給呼叫端）。故改成語言中立的固定字串， label 走「前綴 key ＋片語節點＋後綴 key」（§4-2 前後綴 key 自帶分隔空白）。 **片語還要跟著上一步選的動作換一組**：`ReviewApplyIn.action` 的值域逐字是 `purge_data`／`delete_account`／`freeze`（platform.py），idle 態三顆動作鈕各對一個， 原本不論選哪一顆都要求打「刪除」——選了「凍結逾時帳號」卻被要求打「刪除」。 三組片語由 `data-phrase-<動作>` 承載，React 依選定的動作把可見那一顆換上去。 **刻意不用 `data-text-<態>`／`data-key-<態>` 那組資料槽**：那一族的定義是「繁中原文 ＋ 對應的 i18n key」，而這裡的重點正是**這串字不翻**，掛上去會讓下一個人以為少了一半。 #}
