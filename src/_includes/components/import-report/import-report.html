{# 匯入結果回報：Excel（1-1-6）與 PDF/Word（1-2-1 送出後）共用同一塊，故切成元件（GUIDELINE §3-3 第 1 條）。 出處：gufofaq-saas services/product/app/routers/datasets.py。`import_excel` 與 `batch_import_documents` 兩支的回應同形，都帶 `inserted`／`updated`／`failed` 三個計數 （`_tally`）；`structure`（抽取統計）／`dropped_links`／`unprocessable_tables` 三者是**逐檔**的 （批次端點放在 `results` 的每一項裡），故本元件也做成逐檔一塊、標上檔名——彙總成一份的話， 使用者看得到「有 2 個連結被移除」卻不知道是哪一個檔，那條訊息就不可行動了。 三計數必須一起顯示：`updated` 是「同 external_key 的舊版被取代」，只報「匯入 N 筆」的話， 使用者分不出這次是新增了 N 筆，還是把 N 筆舊資料換掉了。 頁面 include 前 set（GUIDELINE §6，資料因頁面而異）： importCounts = { inserted, updated, failed }（必填） importFileReports = [{ filename, structure?, droppedLinks?, unprocessableTables? }]（選填） structure = [{ labelKey, label, value }]——word 與 pdf 的欄位不同（product app/docx.py 的 DocxStats 是段落/表格/表格列數；app/pdf_tables.py 的 PdfStats 是頁數/表格/表格列數/ 跨頁被切斷的表格/有格線卻抽不出表格的頁數），故做成通用 label-value 列而不是寫死的句子 droppedLinks = { count, urls: [...] }——HTML→Markdown 剝掉的連結 unprocessableTables = [ 描述, ... ]——無法保真轉換的表格；筆數由陣列推導，不另烤一個數字（§6） 被剝除連結區塊是「把連結搬回答案端」的入口：連結在匯入時就從內文剝掉了，要讓它回到答案裡 只能靠〈對話設定 → 出口替換規則〉在生成後替換（product app/routers/settings_hub.py 的 `output_replacements`）。「複製為出口替換規則」把每個網址轉成一條可直接貼進「替換內容」欄的 值 `[${0}](網址)`（`${0}`＝命中的別名文字），別名由租戶自己填——匯入端剝連結時只留得下 href， 拿不到原本的錨文字（product app/html_md.py 的 `_register_link`）。 複製是純前端互動（GUIDELINE §5 ④），行為在 import-report.js 當場做，toast 走 data-toast 委派。 #}
