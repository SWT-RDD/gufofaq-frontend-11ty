{# 別名表管理：**別名表統一管理「誰＝誰」，各功能自己決定要不要套用**。 **為什麼要有這一頁**：別名散在術語表詞條與出口替換規則兩個地方時，最需要它的 QA 直答 （逐字比對）一個都拿不到——使用者打「推廣貿易服務費要怎麼繳」、QA 集裡寫的是 「推貿費要如何繳納？」，同一件事換個說法就命中不到。 **別名只住在一個地方**：術語表沒有別名欄，這一頁也不留任何第二份別名——兩份別名一定會 分岔，而分岔的那一天沒有任何畫面看得出來。 **階段不標在每一列詞條上**：那會變成幾百列 × 四個勾選框，實務上一定被「全選」處理掉， 得到的是假的細緻度。四個套用開關放在設定檔（5-2），一個明確、看得見、一鍵可撤的決定。 上限是契約欄位（§6），**六條界線在這裡宣告**：表名稱 200 字、說明 2000 字、 一張表最多 20000 筆詞條、一筆詞條最多 50 個別名、正式寫法 200 字、單一別名 200 字。 版型比照 3-2_glossaryManagement（新增區＋清單表＋條件開窗 modal）——它就是同一種東西的 管理頁，沒有理由長得不一樣。 **清單刻意不顯示「生效於哪些功能」**：那是設定檔的事，同一張表可以在設定檔 1 用於比對、 在設定檔 2 完全沒用——一欄塞不下，塞了就會說謊。 **不做「何時查閱／補充指示／查詢正規化 regex」**：那三個是術語表的工具屬性，別名表不生成 任何工具。 #} {# id＝這張別名表的識別碼。**不可拿 loop.index 當列鍵**：這張表刪得掉列， 位置不是身分——刪掉前一列之後，後面每一列的列鍵都會往前頂一格，React 端的 key 與逐列 動作的目標會一起指錯人（§6 列鍵）。 示範 3 張：一張大的、一張小的、**一張空的**——空表要看得出「詞條數 0」不是壞掉（§5 每個 分支都要看得到）。 **「別名總數」這一格逐張表讀得到，不是從詞條數推導的**：一張表「有幾個詞條」與「總共 登記了幾個別名」是兩個決定（詞條數上限與每一筆詞條的別名數上限是兩條不同的界線）， 所以它自成一欄。 **值域含 0**（空表就是 `0`），所以這一格不用真值判斷、也不留「—」那一態：那顆破折號的語意是 「量得到、只是這一刻還沒有值」（§6 三種哨兵），拿它承載一個量到的 `0` 會讓值班的人分不出兩者。 #} {% set aliasTables = [ { id: 12, name: "關務通用別名", desc: "報關、稅費、單證的常見簡稱與口語說法。", entryCount: 8, aliasCount: 19 }, { id: 9, name: "系統別名", desc: "內部系統與模組的舊稱、代號。", entryCount: 3, aliasCount: 5 }, { id: 7, name: "待整理別名", desc: "", entryCount: 0, aliasCount: 0 } ] %} {# 第二句一定要有：不然使用者建完表會以為它就生效了。 #}

{# 新增別名表：只有名稱（必填）與說明。送出鈕的 data-toast 列全結果（§5 矩陣③）， warning 段對回那兩欄的驗證（空名、長度上限）。 **沒有「名稱已存在」那一段**：表名稱沒有任何唯一性檢查，同名建得起來。列一個不可能發生 的結果，與只演成功一樣是說謊（§5）。 **第 5 段：到達每租戶的張數上限**（30 張，在這裡宣告；術語表與別名表兩族各自這麼多）。 配額算在租戶身上，第 31 張會被擋下。 **它是 warning、不是 error**：使用者刪掉用不到的表就建得起來。 **而且一定要有自己的一段**：併進第 4 段「建立失敗，請稍後再試」就是把一個永久的拒絕 演成暫時故障——使用者的下一步變成「等一下再按一次」，而那永遠不會成功。 ⚠️ 第 5 段刻意不帶「現在幾張／上限幾張」，理由同 3-2：`data-toast` 是屬性型譯文，數字要有 一處常駐可見的節點承載，那一處是下方「別名表清單」標題列的計數（`已 N / 30 張`）。 #}
