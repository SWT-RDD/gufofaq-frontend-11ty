{# 別名表管理（SaaS 新需求，真 app 無對應）。逆向自 GufoRAG chatbot `app/models/alias.py` 與 `app/services/alias.py`：**別名表統一管理「誰＝誰」，各功能自己決定要不要套用**。 在此之前別名散在兩個地方（術語表詞條的 aliases、出口替換規則的 aliases），而最需要它的 QA 直答逐字比對完全沒有——使用者打「推廣貿易服務費要怎麼繳」、QA 集裡是「推貿費要如何繳納？」， 實測 4 次只命中 1 次。術語表的 `aliases` 欄已於 2026-08-07 隨上游移除（見 chatbot `db/database.py` 的那句「別名一律住在 alias_entries」），本站同輪拿掉，不留、不 deprecate。 **階段不標在每一列詞條上**：那會變成幾百列 × 三個勾選框，實務上一定被「全選」處理掉， 得到的是假的細緻度。三個套用開關放在設定檔（5-2），一個明確、看得見、一鍵可撤的決定。 上限是契約欄位（§6），出處＝chatbot `app/services/alias.py`： `MAX_TABLE_NAME_LEN = 200`／`MAX_DESCRIPTION_LEN = 2000`／`MAX_ALIAS_ENTRIES_PER_TABLE = 5000`／ `MAX_ALIASES_PER_ENTRY = 50`／`MAX_CANONICAL_LEN = 200`／`MAX_ALIAS_LEN = 200`。 版型比照 3-2_glossaryManagement（新增區＋清單表＋條件開窗 modal）——它就是同一種東西的 管理頁，沒有理由長得不一樣。 **清單刻意不顯示「生效於哪些功能」**：那是設定檔的事，同一張表可以在設定檔 1 用於比對、 在設定檔 2 完全沒用——一欄塞不下，塞了就會說謊。 **不做「何時查閱／補充指示／查詢正規化 regex」**：那三個是術語表的工具屬性，別名表不生成 任何工具。 #} {# id＝別名表主鍵（chatbot `alias_tables.id`）。**不可拿 loop.index 當列鍵**：這張表刪得掉列， 位置不是身分——刪掉前一列之後，後面每一列的列鍵都會往前頂一格，React 端的 key 與逐列 動作的目標會一起指錯人（§6 列鍵）。 示範 3 張：一張大的、一張小的、**一張空的**——空表要看得出「詞條數 0」不是壞掉（§5 每個 分支都要看得到）。別名總數從詞條推導不出來（它是各列別名個數的總和，切版沒有算術）， 故與詞條數一樣是端點回的欄，兩個都當資料給。 #} {% set aliasTables = [ { id: 12, name: "關務通用別名", desc: "報關、稅費、單證的常見簡稱與口語說法。", entryCount: 8, aliasCount: 21 }, { id: 9, name: "系統別名", desc: "內部系統與模組的舊稱、代號。", entryCount: 3, aliasCount: 5 }, { id: 7, name: "待整理別名", desc: "", entryCount: 0, aliasCount: 0 } ] %} {# 第二句一定要有：不然使用者建完表會以為它就生效了。 #}
