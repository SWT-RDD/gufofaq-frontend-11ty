{# 別名表管理（SaaS 新需求）。逆向自 GufoRAG chatbot 的別名表模型與服務層： **別名表統一管理「誰＝誰」，各功能自己決定要不要套用**。 **為什麼要有這一頁**：別名散在術語表詞條與出口替換規則兩個地方時，最需要它的 QA 直答 （逐字比對）一個都拿不到——使用者打「推廣貿易服務費要怎麼繳」、QA 集裡寫的是 「推貿費要如何繳納？」，實測 4 次只命中 1 次。 **別名只住在一個地方**：術語表沒有 `aliases` 欄（GufoRAG chatbot 逐字寫著「別名一律住在 alias_entries」），這一頁也不留、不 deprecate 任何第二份別名——兩份別名一定會分岔， 而分岔的那一天沒有任何畫面看得出來。 **階段不標在每一列詞條上**：那會變成幾百列 × 四個勾選框，實務上一定被「全選」處理掉， 得到的是假的細緻度。四個套用開關放在設定檔（5-2），一個明確、看得見、一鍵可撤的決定。 上限是契約欄位（§6），出處＝GufoRAG chatbot 的這六顆常數： `MAX_TABLE_NAME_LEN = 200`／`MAX_DESCRIPTION_LEN = 2000`／`MAX_ALIAS_ENTRIES_PER_TABLE = 20000`／ `MAX_ALIASES_PER_ENTRY = 50`／`MAX_CANONICAL_LEN = 200`／`MAX_ALIAS_LEN = 200`。 版型比照 3-2_glossaryManagement（新增區＋清單表＋條件開窗 modal）——它就是同一種東西的 管理頁，沒有理由長得不一樣。 **清單刻意不顯示「生效於哪些功能」**：那是設定檔的事，同一張表可以在設定檔 1 用於比對、 在設定檔 2 完全沒用——一欄塞不下，塞了就會說謊。 **不做「何時查閱／補充指示／查詢正規化 regex」**：那三個是術語表的工具屬性，別名表不生成 任何工具。 #} {# id＝別名表主鍵（chatbot `alias_tables.id`）。**不可拿 loop.index 當列鍵**：這張表刪得掉列， 位置不是身分——刪掉前一列之後，後面每一列的列鍵都會往前頂一格，React 端的 key 與逐列 動作的目標會一起指錯人（§6 列鍵）。 示範 3 張：一張大的、一張小的、**一張空的**——空表要看得出「詞條數 0」不是壞掉（§5 每個 分支都要看得到）。 **「別名總數」這一格上游回得出來**：GufoRAG chatbot 的 `_table_to_dict` 把 `alias_count` 列為 **必填具名參數**（沒有預設值，四個呼叫端都得自己算），product 原樣代理。 為什麼要單獨一欄：一張表「有幾個詞條」與「總共登記了幾個別名」是兩個決定 （`MAX_ALIAS_ENTRIES_PER_TABLE` 與 `MAX_ALIASES_PER_ENTRY` 是兩條不同的上限）， 而它從詞條數推導不出來。**上游那一側的符號名是 `_table_to_dict`**：改版時 grep 它一次就知道 這一格還在不在（§4「上游還沒有 X」是最會過期的一種斷言——這一條就是主張成功之後上游補上的）。 **值域含 0**（空表就是 `0`），所以這一格不用真值判斷、也不留「—」那一態：那顆破折號的語意是 「量得到、只是這一刻還沒有值」（§6 三種哨兵），拿它承載一個量到的 `0` 會讓值班的人分不出兩者。 #} {% set aliasTables = [ { id: 12, name: "關務通用別名", desc: "報關、稅費、單證的常見簡稱與口語說法。", entryCount: 8, aliasCount: 19 }, { id: 9, name: "系統別名", desc: "內部系統與模組的舊稱、代號。", entryCount: 3, aliasCount: 5 }, { id: 7, name: "待整理別名", desc: "", entryCount: 0, aliasCount: 0 } ] %} {# 第二句一定要有：不然使用者建完表會以為它就生效了。 #}

{# 新增別名表：只有名稱（必填）與說明。送出鈕的 data-toast 列全結果（§5 矩陣③）， warning 段對回 chatbot 的 `validate_alias_table_metadata`（空名、長度上限）。 **沒有「名稱已存在」那一段**：GufoRAG chatbot 的 `create_alias_table` 只跑那一支驗證就 db.add， 而 GufoRAG chatbot 的 `alias_tables.name` 是 `Column(String(200), nullable=False)`——無 unique、 無 UniqueConstraint、全檔零 IntegrityError 分支。列一個上游產不出來的結果，與只演成功一樣是說謊（§5）。 **第 5 段：到達每租戶的張數上限。** product 的 `create_alias_table` 第一行就是 `await _assert_table_quota(...)` → 第 31 張回 400 `table.too_many_for_tenant`。 **執法點在 product**（`MAX_TABLES_PER_TENANT = 30`，術語表與別名表共用同一顆常數、 兩族各自這麼多），不在 GufoRAG chatbot——那一側的 `tenant_id` 是呼叫端自填的 tag、 當不了配額鍵（換一個 tag 就再拿 30 張）。 **它是 warning、不是 error**：使用者刪掉用不到的表就建得起來。 **而且一定要有自己的一段**：併進第 4 段「建立失敗，請稍後再試」就是把一個永久的拒絕 演成暫時故障——使用者的下一步變成「等一下再按一次」，而那永遠不會成功。 ⚠️ 第 5 段刻意不帶「現在幾張／上限幾張」，理由同 3-2：`data-toast` 是屬性型譯文，數字要有 一處常駐可見的節點承載，那一處是下方「別名表清單」標題列的計數（`已 N / 30 張`）。 #}
