{# 切塊設定：`POST /datasets` 的 `DatasetIn` 三欄——`chunk_size`／`chunk_overlap`／ `prepend_title_each_chunk`（product `app/routers/datasets.py`）。 **為什麼本輪補畫**：這三個參數在切版與 apps/web 兩邊原本都是零落點（§3-2：request 收得下的 每個參數都要在畫面上有落點），而它們決定這個資料集之後**所有**檔案怎麼被切——沒有落點等於 這個決定只能靠直接打 API，而使用者連它存在都不知道。 **為什麼版位在建立頁**：`_assert_chunk_params_still_settable`（同檔）是一道 409 硬閘門——這個 資料集只要做過一次走 folder 管道的「檔案上傳」匯入，三欄就再也改不動（folder 管道每資料集 一支、建立時參數就固定，product 沒有任何路徑會刪它），所以「現在」是唯一保證改得動的時機。 3-1-3 詳細頁另有一份（走 `PATCH /datasets/{id}` 的 `DatasetPatchIn`），那裡才撞得到 409。 **值域出處**（§4 數字欄三件套的常數來源，同檔）：`_CHUNK_SIZE_MIN` = 100／`_CHUNK_SIZE_MAX` = 8000 收在 `DatasetIn.chunk_size` 的 `Field(ge=…, le=…)`，預設 1000；`chunk_overlap` 是 `Field(default=200, ge=0)`——**上界不是常數**，而是跨欄約束 `_assert_overlap_below_size` （overlap 必須小於 size，違反回 422），所以 max 不寫死、由可見提示承載那句話； `prepend_title_each_chunk` 預設 False。三欄都是整數／布林 ⇒ step="1"。 **值載體不另創 hook class**：本表單既有的 `#datasetName`／`#datasetGroup` 都是純 id 契約 （React 正本 apps/web `datasets/new/page.tsx` 直接讀自己的 state 送 body），三顆新欄位沿用 同一種記號（§5 矩陣：class 或 id 擇一）。送出動作是下面那三張卡片（React 端＝先 POST /datasets 帶這三欄、再導去該類型的上傳流程），故本區塊沒有自己的送出鈕、也不掛 data-toast。 #}
切塊設定
{# 代價寫在做這個決定的控制項旁邊、且排在觸發鈕（下面三張卡片）之前（§3-2）。 #}

切塊參數只在建立擷取管道時送給上游，所以只影響之後匯入的檔案；已經匯入的內容不會重新切塊。

而且這個資料集只要做過一次「檔案上傳」匯入，這三個值就再也改不動，之後不論從哪一條路匯入都只能沿用現值——請在這裡決定好。

{# 區間是資料不是譯文（§3-2），數字獨立成不翻的節點。 #} 100 – 8000
≥ 0，且必須小於切塊大小

開啟後每一塊的開頭都會補上這份文件的標題，檢索時比較不會斷章取義；代價是每一塊少一點放正文的長度。
