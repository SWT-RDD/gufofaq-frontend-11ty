{# 切塊設定：`PATCH /datasets/{id}` 的 `DatasetPatchIn` 三欄——`chunk_size`／`chunk_overlap`／ `prepend_title_each_chunk`（product `app/routers/datasets.py`），現值由 `DatasetDetailOut`（同檔 `get_dataset`）的同名三欄回。3-1-2 建立頁有同一組欄位（走 `DatasetIn`），兩處是同一份設定的兩個消費點，所以約束提示兩邊都要有（§4：同一個欄位在同一頁 ／同一支端點的多個入口，每一處都要有）。 **為什麼補畫**：這三個參數在切版與 apps/web 兩邊原本零落點（§3-2），而它們決定之後匯入的檔案 怎麼被切。 **值域出處**（§4 數字欄三件套的常數來源，同檔）：`_CHUNK_SIZE_MIN` = 100／`_CHUNK_SIZE_MAX` = 8000 （`Field(ge=…, le=…)`），`chunk_overlap` 是 `Field(ge=0)` ⇒ **沒有上界常數**，真正的上界是 跨欄約束 `_assert_overlap_below_size`（overlap 必須小於 size），所以 max 不寫死、那句話由可見 提示承載；三欄都是整數／布林 ⇒ step="1"。示範值＝`DatasetIn` 的預設（1000／200／false）。 **為什麼欄位照樣渲染成可編輯的**：`_assert_chunk_params_still_settable`（同檔）是一道 409 硬閘門 （這個資料集只要有 folder 管道就擋），但 `DatasetDetailOut` **沒有任何欄位講得出這個資料集是不是 已經被鎖住**——前端拿不到那個事實，就不可能在使用者打字之前把欄位 disabled 掉；能誠實做的只有 「照常給改，改不動時由 409 那一段 warning 說清楚」（§5：分支結果由 data-toast 演）。 📌 交辦：請 product 在 `DatasetDetailOut` 補一個布林（例如 `chunk_params_locked`，判準就是 `_assert_chunk_params_still_settable` 那兩條證據的聯集），這一區才能在進頁的當下就說「這個資料集 已經鎖住了」，而不是等使用者填完按下去才知道（§4 切版主張需求）。 儲存鈕是③直接送 API 的鈕 → `data-toast` 列全結果；hook 用 `js-save-chunk-params`（全站 scss 不引用）。 #}
