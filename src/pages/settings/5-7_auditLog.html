{# 查詢區：操作類型篩選（singleSelect，對照後端 GET /audit?action= 精確比對）；此靜態頁列代表性選項， React 端列完整操作類型清單。真實頁 tbody 由 React 依查詢結果渲染，此處以 set+for 資料化示範 3 筆。 **本頁的四顆篩選控制項全部是「值載體」**（§5 組合矩陣②：值交給 React 讀去送查詢參數， 成敗看後端，click 委派也抓不到 select 的 change）——不是只有掛了 hook 的那一顆。 四顆是：`#auditActionSelect`（action）／`#auditTenantInput`（tenant_id）／ `#auditScopeAllInput`（scope=all）／`#auditOperatorInput`（operator）。 **React 綁定記號擇一即可，class hook 或 id 契約都算**（§5 矩陣那一條，正典是 2-2-1 以 `#knowledgeConfigSelect`／`#llmModelSelect` 綁定的那兩顆 select）：這四顆各自有唯一 id， 其中 `#auditTenantInput` 另外掛了 `.js-audit-tenant`——那**不是本頁的規矩**，是既成事實： saas 端已經引用它（`apps/web/app/(app)/audit/page.tsx` 的 `className="form-control js-audit-tenant"`）， §5「hook 一經 saas 端引用即凍結，改名＝跨 repo 遷移」⇒ 不為了四顆一致而補三顆，也不為了風格一致而拿掉它。 （原本這裡只替那一顆寫了「值載體 → 只掛 hook class」的理由，讀起來像本頁對值載體的通則， 而另外三顆一顆 hook 都沒有——同一頁對同一種控制項寫了兩套說法。） 租戶（指定 tenant_id／全部租戶 switch 送 scope=all）與操作者（送 operator=）三個篩選欄位要**平台角色**才看得到， 而那是 auditor 亦有的能力：product app/routers/audit.py 的 list_audit 以 is_platform_auditor （platform_role ∈ {auditor, admin}）判斷 scope=all／tenant_id／operator，該檔自註「用 is_platform_admin 判斷會把唯讀稽核員一起排除掉」。故上列這幾欄一律掛 data-platform-role="auditor"（§5 兩級可見性）， **它們都是值控制項（switch／input），不是動作鈕**，所以套的是 §5 兩級可見性的另一半： 低於該級時**照渲染但 disabled**，不是不渲染——狀態要看得見才稽核得到。 （原本這裡寫「決定是否渲染」，照著做會做出規則的反面；5-6-1／5-6-3 兩頁寫的才是對的。） 此靜態頁展示的是有平台角色、可操作時的完整版面。 #}
