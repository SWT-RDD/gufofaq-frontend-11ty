{# 萃取 API 金鑰管理（獨立設定頁）。SaaS 新需求，逆向自 product extract.py： 每租戶一把金鑰，供外部程式以 X-API-Key 標頭呼叫萃取端點（國家／時間）與資料 API （/api/v1）；重新產生後舊金鑰立即失效。/api-key 的 GET／POST 皆僅租戶管理者可用 （require_admin，比照 widget-tokens）。 **明碼只在產生的那一次出現**：product 端只存雜湊，重新載入後只回得出末四碼 hint。 ## `ApiKeyOut` 三個欄位、三種態，逐態成對參數（§5：`{% if %}` ＋ 參數，不用 `.hidden`） 正本 `extract.py` 的 `ApiKeyOut` 只有三欄：`api_key`（明碼，**僅產生當下**）、`api_key_hint` （前綴＋末四碼，`app/security.py` 的 `_key_hint` ⇒ 形狀是 `sk_…` ＋末四碼）、`has_key`。 `POST /api-key` 回 `(api_key, api_key_hint, has_key=True)`；`GET /api-key` 在沒有金鑰時回 `has_key=False`、有金鑰時回 `(api_key_hint, has_key=True)` 而**永遠不回明碼**。 三態逐一對回這三欄，切版參數： · `extractKeyHasKey` ＝ `has_key`。false ⇒ 這個租戶還沒有金鑰：不畫金鑰欄，鈕改成 「產生金鑰」而且**不走二次確認**（沒有舊金鑰會失效，那顆確認窗的內文在這一態是假的）。 · `extractKeyPlain` ＝ `api_key`。有值＝**剛產生**那一次：完整明碼 ＋「唯一一次」紅字 ＋ 顯示/隱藏 ＋ 複製。 · `extractKeyHint` ＝ `api_key_hint`。恆有（has_key 為真時），是「已存在」那一態畫面上 唯一看得到的東西——**這一態才是使用者日常會看到的那一個**（只要重新整理過一次就是它）， 而它原本全站零落點：`api_key_hint` 與 `has_key` 兩欄畫面上都沒有家，檔頭卻宣稱本頁有兩種態。 切版示範「剛產生」態；另外兩態的可見示範在元件庫頁（§5：`{% if %}` 的另一支在唯一使用頁上 恆為某一值，等於沒有人看過它的長相）。 #}

如何呼叫萃取 API
{# text 長度 2–5000 是 product 真的會擋的界線（`app/routers/extract.py`： `if not (2 <= len(text) <= 5000): raise HTTPException(...)`，對齊舊系統），不是文案裡的 舉例數字——上限改了這裡也要跟著改，故獨立成資料節點（§3-2）。 `mode 1=國家、2=時間、3=兩者` 與句尾的 `429` 維持譯文：前者是**枚舉值**不是界線 （`body.mode not in (1, 2, 3)` 判的是值域不是夾輸入），後者是固定的 HTTP 狀態碼， 兩者都不是「改了後端常數這裡要跟著改」的那一類數字。 #}

以 X-API-Key 標頭呼叫；mode 1=國家、2=時間、3=兩者；text 長度 2–5000 字；額度用罄回 429。

curl -X POST "https://<your-host>/api/extract/country-or-time" \
  -H "X-API-Key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"我們下週三在東京開會","mode":3}'
