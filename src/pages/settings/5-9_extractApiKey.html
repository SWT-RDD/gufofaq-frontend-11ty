如何呼叫萃取 API
{# text 長度是 product 真的會擋的界線：`app/routers/extract.py` 的 `MIN_EXTRACT_TEXT_LEN`（2）／`MAX_EXTRACT_TEXT_LEN`（5000），判在 `if not (MIN_EXTRACT_TEXT_LEN <= len(text) <= MAX_EXTRACT_TEXT_LEN)`。 （先前這裡引的是 `if not (2 <= len(text) <= 5000)` ——那一行**在被引檔案裡逐字不存在**， 而且沒有給任何符號名：repo ＋ 檔 ＋ 疑似原文三者齊全，看起來完全合規，正是 §3-2 最難抓的那種假出處。）不是文案裡的舉例數字 ⇒ 獨立成資料節點（§3-2）。 **契約已經到了**：`app/routers/extract_limits_contract.py` 投影成 `GET /extract/limits` 的 `text.length`（`ops_limits.EXTRACT_LIMIT_GROUPS`），下一輪把這個節點接上它即可。 排法（en dash 前後帶空白）對齊 `apps/web` `lib/useLimits.ts::formatBound` 既有的界線呈現慣例（`1 – 10`）。 **`time_reference` 是同一個 group 的姊妹界線**（§3-2：group 的姊妹界線要一起檢查有沒有落點）： `ExtractIn` 收三欄（`text`／`mode`／`time_reference`），第三欄與 `text` 一樣**原文渲進提示詞**， 故上游也夾了 `MAX_EXTRACT_TIME_REFERENCE_LEN`（200，`extract.time_reference_too_long` 那道 400）， 並且**為了這件事補了投影**（`EXTRACT_LIMIT_GROUPS` 的 `text.time_reference_len`）—— 先前這一頁對它一個字都沒有，持金鑰的整合方在那一欄打超過上界時，畫面上沒有任何地方 講得出上界是多少。下面那句說明與 curl 範例都補上它。 `mode 1=國家、2=時間、3=兩者` 與句尾的 `429` 維持譯文：前者是**枚舉值**不是界線 （`body.mode not in (1, 2, 3)` 判的是值域不是夾輸入），後者是固定的 HTTP 狀態碼， 兩者都不是「改了後端常數這裡要跟著改」的那一類數字。 #}

以 X-API-Key 標頭呼叫；mode 1=國家、2=時間、3=兩者；text 長度 2 – 5000 字；選填的 time_reference（發文時間基準）最多 200 字；額度用罄回 429。

curl -X POST "https://<your-host>/api/extract/country-or-time" \
  -H "X-API-Key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"我們下週三在東京開會","mode":3,"time_reference":"2026-07-14"}'
