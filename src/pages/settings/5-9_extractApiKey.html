{# 萃取 API 金鑰管理（獨立設定頁）。SaaS 新需求，逆向自 product extract.py： 每租戶一把金鑰，供外部程式以 X-API-Key 標頭呼叫萃取端點（國家／時間）與資料 API （/api/v1）；重新產生後舊金鑰立即失效。/api-key 的 GET／POST 皆僅租戶管理者可用 （require_admin，比照 widget-tokens）。 **明碼只在產生的那一次出現**：product 端只存雜湊，重新載入後只回得出末四碼 hint。 故本頁有兩種態：剛產生（顯示完整金鑰＋「唯一一次」警語，顯示/隱藏可用）與 已存在（只顯示 hint＋「只保存雜湊」說明，顯示/隱藏無意義）。 無金鑰首次態（尚未產生）由 React 依 API 呈現，切版以「剛產生」態示範。 #}

此金鑰供外部程式以 X-API-Key 標頭呼叫萃取 API（國家／時間）與資料 API（/api/v1），請妥善保管。重新產生後舊金鑰會立即失效。

系統只保存金鑰的雜湊值，無法再顯示明碼；遺失請重新產生。

這是這把金鑰唯一一次顯示明碼——關閉或重新整理本頁後就只看得到末四碼。請現在複製並妥善保存。

{# 示範值的長度是推導值，不是隨手打的：product `app/security.py` 的 `new_api_key()` ＝ `_API_KEY_PREFIX + secrets.token_urlsafe(32)` ⇒ 32 bytes 的 base64url 是 43 字元、加 `sk_` 共 46 字元。 這一格預設是 `type="password"`，**遮罩點數就等於字面量長度**——原本只給 35 字元， 等於畫面上那排點永遠比真金鑰短十顆，欄寬與換行也就沒有被真的驗過。 #}
{# 顯示/遮蔽切換＝純前端互動（無業務、無 API），由 ui/reveal-input 以 data-reveal-target 委派切 type； 兩態文字與 key 由 data-text-*/data-key-* 提供，JS 不寫死字串（見 §4-2/§5）。 狀態語意走換標籤、不掛 aria-pressed（兩者並用會念出矛盾，見 reveal-input.js）。 #}

如何呼叫萃取 API

以 X-API-Key 標頭呼叫；mode 1=國家、2=時間、3=兩者；text 長度 2–5000 字；額度用罄回 429。

curl -X POST "https://<your-host>/api/extract/country-or-time" \
  -H "X-API-Key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"我們下週三在東京開會","mode":3}'
