# 切版的架構判準

這一份講的是**判斷怎麼下**。條文級的規格（哪一顆 token 屬哪一桶、哪一種字面要不要掛 key、
屬性後綴有哪五個）正本在 `GUIDELINE.md` §4／§4-2 與 `tests/_lib/color.mjs`，這裡不抄第二份——
抄過來的那一份不會有人回頭更新，而它與正本長得一模一樣，讀的人分不出自己讀的是哪一種。

## 架構不妥協，數值差不多

- **判準一句話：問「這會不會變成設計師照抄的壞架構？」** 不會的話，按鈕填什麼色、寬度幾 rem 差不多即可，不需像素級精確。
- **為了更乾淨的架構做大規模重構永遠值得。** 成本／時間／破壞性一律不是理由，不要為了省事而遷就現有結構。
- 遇到重複／共用需求：要嘛乾淨共用既有元件、要嘛開乾淨新元件。**不要用「全部 scope 在某個 wrapper 底下」這種 hack 折衷。**
- 但**不要為了對齊真實數值而過度工程**：不為單一頁面補一組新的 size／border 變體，用既有元件 + utility 就好。
- 這條只適用切版本身。下游是像素級照抄，見 `slicing-source-of-truth`。

## 一個元件還是兩個：只看 DOM 骨架

- 骨架相同、只差資料或修飾詞（內容不同、`position` 流動 vs absolute）＝**該是一個元件**，差異走參數 + modifier class。骨架本身不同才分兩個，並把可複用的原子抽出來共用。
- **「內容不同／定位不同」不是分兩顆的理由。** 拿內容當理由，任何兩顆元件都能說成不同的——判準必須是結構才判得動。重複的骨架會在下游被複製 N 次，每一份各自走樣。
- 合併時**容器各自保留**：抽出共用的內層，外層寬高由各自的頁面決定。
- 反過來，**「這顆只有一顆 class」不是可以交給使用頁手抄的理由**：判準是「檔頭契約寫不寫得出一串缺一不可的節點」。寫得出來就要鎖成元件（下游同理，見 `REACT-CONVERSION.md` §⓪），寫不出來才是使用頁自己貼 class。

## hook class 與 data-* 是轉換契約，不是死碼

- 沒有樣式、沒有行為的 hook class（`.js-*`、`.btn-delete-file`、`.copyBtn`）與資料屬性（`data-index`、`data-type`）是「這顆按鈕該接什麼」的標記，下游據此接上真正的邏輯。**預設保留。**
- **不要盲目補靜態行為。** 只有「無條件開窗」的觸發器才可以掛 `data-open-modal`；有條件開窗的（依權限決定開哪一份 modal、先記住要刪哪一列、驗證到空欄位才跳）留 hook class。掛上靜態 `data-open-modal` 等於在 markup 裡寫一句謊話。
- 彈窗的「看得見」保證放在元件總覽頁的示範觸發器，不是真實頁。
- 「這是死碼」的結論不能拿自己的舊註解背書——證據只能是實際檔案，見 `carpet-audit`。

## token 是角色契約

- **一顆 token 只能有一個角色**（§4）。數值接近某個需求不代表可以借用——深色模式會拆穿，因為每個角色在深色下的提亮方向不同（文字提亮、填充壓深）。
- 要一個「語意色的前景」就**新增對應的 `--*-text`**（比照 `--danger-text`／`--success-text`），light/dark 各給值，疊 `--surface`／`--surface-raised` ≥ 4.5:1。**不要借填充桶（`--success`）或 chrome 桶（`--border`）的 token。**
- 遮罩圖示（`icon-mask`）的 `$ink` 是**前景**，只能來自文字族或 `--brand-ink`。
- **角色表的唯一正本是 `tests/_lib/color.mjs` 的 `COLOR_ROLES`**，而且它是**窮舉**的：新增一顆顏色 token 沒歸類，測試就紅。要知道某顆 token 現在算哪一種，去讀那一份，不要憑印象。
- **陷阱在「哪一種疊法有人在看」，不在「哪一桶被豁免」。** 角色桶只管「這顆 token 自己疊在 surface 上讀不讀得到」；真正要靠人手維護的是兩張**成對清單**——`pairs`（前景疊背景，≥4.5:1）與 `graphicPairs`（圖形記號／元件邊界，≥3:1）。它們只列 markup 裡真的疊在一起的組合，所以**畫出一種新的疊法時要自己去補一筆**，沒補就沒有任何一條測試看得到它。chrome 桶只是「不做內文對比斷言」、不等於免檢查：被列進 `graphicPairs` 的 chrome token（switch 的軌道與把手、storage-bar 的軌道）照樣有 3:1 斷言。
- **換了列底色就要重算那一列的所有前景**（停用列、tint 面、sunken 面），並把新的疊法登記進 `pairs`／`graphicPairs`。只把重算出來的數字寫進 scss 註解、沒進清單，就能無聲回歸。
- 元件總覽頁的 `--gl-*` 也要 light/dark 兩套、也要填充／文字分家——一顆兼填充與文字在深色下無解。

## i18n 模型與範圍

**繁中＝原文（source），留在字串出現的地方；英文＝翻譯檔 `src/i18n/en.json`。** markup 的繁中不可抽進 `zh.json`——那會讓 HTML 變空殼、破壞無 JS 基準、也破壞「`data-i18n="key">文字</` → `{t("key")}`」的轉換契約。

**判準只有一句：這個字串是誰打的。** 產品打的（UI chrome）就要有 key；租戶或使用者打的（資料）就不要有——掛了 key 等於把使用者自己命名的東西改寫成英文。含糊的邊界照 §4-2 逐條判，別在這裡另立一套。

**要翻（UI chrome）：** nav／breadcrumb／按鈕／表單 label／固定表頭 `<th>`／區塊標題／pagination／控制項的可及名稱／分頁標題（front matter 的 `titleKey` → `<html data-page-title-key>`）。

**不譯（資料）：** 聊天訊息、AI 回答、提示詞全文、免責聲明內文（標題是 chrome、有譯）、示範檔名／資料集名／記錄名、表格 cell `<td>` 值、示範 Excel 自身的欄位名（要對應到的**目標**欄位 `field.<key>` 才是產品預設名、有譯）、租戶自己取的顯示名與群組名、type-to-confirm 要打出來的那個片語（它若隨語系改變，同一道閘在兩個語系要求不同的輸入）。`<option>` 的 `value=` 是表單值、不翻；看得見的那段 `<option>` 文字照上一句的判準走。

**兩個最常被判錯的地方：**

- **元件 js 換字的節點照樣在範圍內**，只是它不走 `data-i18n`：繁中原文與 key 分別掛在**同一顆元素**上（單一值用 `data-<槽名>` ＋ `data-<槽名>-key`，正典 `ui/multi-select` 的 placeholder；兩態切換用 `data-text-<態>` ＋ `data-key-<態>`，正典 `ui/theme-toggle`／`components/prompt-edit`），js 拿 key 走 `GufoI18n.t(key, "繁中原文")`。這一族與 `data-i18n` 節點受同一批一致性檢查（同 key 繁中一致、同文異 key、英譯撞句）。
- **showcase 不是整片豁免。** 元件庫頁自己在 i18n 範圍內；豁免的是「**寫給切版者看的示範素材**」——展示片段的欄名／頁籤名／示範列，以及 showcase 自己加的變體名與態名（它們出貨時不帶過去，掛 key 就是在 `en.json` 種一顆永遠讀不到的條目）。反過來，碰巧住在 showcase 頁上的 app 文字（`ui/subscription-gate` 的面板、「React 條件文案」那一節）照樣要掛 key。分界是**這句話會不會出現在使用者的畫面上**。⚠️ **不可以拿「這一頁有沒有語言切換鈕」當判準**：`lang-toggle` 全站載入、依 `localStorage` 套用，沒有那顆鈕的頁（走 `layouts/base` 的錯誤頁）照樣會被翻。

**迴圈內的控制項不掛靜態 `aria-label`**：一張表十幾列全叫「規則」，報讀器會連著唸十幾次同一個字，聽不出正在改哪一條。改成 `aria-labelledby` 指「本列的辨識欄 ＋ 欄表頭」；那張表沒有辨識欄時，列的名字就是控制項自己——這是版位問題，回頭補一顆辨識欄，不是拿一顆假 label 蓋過去。

**由 JS 產生的字串**沒有 markup 可住，沿用同一規則：`GufoI18n.t(key, "繁中原文")`（lang-toggle 匯出）。元件除了寫入文字，也要**同步改寫 `data-i18n` / `data-i18n-title` 的 key**，並監聽 `gufo:langchange` 依「當下狀態」重畫（accordion 展開↔收合、prompt-edit、multi-select 空狀態）。

**驗證要 runtime，不能只靠靜態掃描**：靜態掃描（找沒 `data-i18n` 的可見繁中）抓不到 JS 機制 bug——取文字節點時抓到 `<img>` 前的換行空白、漏換真正標籤，就要改成「第一個非空白文字節點」。完成前用 playwright 在 `localStorage.lang='en'` 下逐頁實查可見繁中。
