# 地毯式審查

## 地毯式＝LLM 逐檔讀，掃描只是佐證

- 「地毯式審查」**不是**寫一支掃描腳本跑一跑，而是**派 LLM 拿規則逐條、逐檔比對所有元件、所有頁面、所有樣式**。
- 規則裡大半條文（桶歸屬、該不該切元件、a11y 可及名稱、資料契約、跨元件覆寫的「用 vs 改」）需要語意判斷，正則抓不到。
- 機器掃描只當**線索**餵給 agent 查證，不可拿來當結論。能穩定機器驗的才固化成測試（見 `verification-that-can-fail`）。

## 派工規格

每個審查 agent 的 prompt 必須包含：

1. **完整讀檔**，不是 grep 片段。
2. 每筆違規必須引用 `檔案:行號 + 原文`，**沒證據不准報**，另開 `[存疑]` 區。
3. **已知假陽性陷阱清單**，否則每個 agent 都會重報同樣的假違規：`<a>` 是 transparent content model 可包區塊、HTML 註解內不是 markup、`GufoI18n.t(key,"繁中")` 第二參數是 fallback、showcase 頁不譯、`_normalize`／`_base` 可用裸元素選擇器、散文裡的 `style="…"` 範例不是行內樣式。
4. **禁止自己跑 `npm run build` / `npm test`**——`build:clean` 會清空 `dist/`，讓跑在 dist 上的結構測試中途讀到 ENOENT，產生數十條與規則無關的假紅（甚至「dist 只掃到 0 個 html」這種總開關斷言）。假紅比沒跑更貴：審查員會據此誤判規則已壞，或因為看不到綠而不敢報。改用「逐條讀 `tests/rules/` 底下的測試原始碼判斷哪些已被守住」；真要跑就開 `git worktree` 隔離副本。主線的最終驗證等所有 agent 結束後單獨跑。

## 扇出不縮水

- 每一輪用同一組切片：**ui 分 3 段、components 分 2 段、pages+layouts、全域 scss、JS+i18n 橫切、root 規範文件、測試盲點，再加一個專門對抗上一個 commit 的**。
- **切片數跟著母體走、不寫死**，也不因為「上一輪已經查過」而縮減。把十幾個切片塞給 1 個 agent，它必然改成抽樣——一個 agent 讀 82 個資料夾是抽樣，不是地毯。
- subagent 崩掉（額度／API error）＝**它負責的那塊沒有被審過**。恢復後重跑，不可用主線輕掃頂替、也不可在回報裡算成已覆蓋。真的不重跑，就在回報裡**明列哪塊只有部分覆蓋、覆蓋到什麼程度**。主線輕掃 ≠ 專責 agent 的深度；runtime 綠 ≠ 源碼級對抗重讀。

## 上一輪的修正是下一輪的頭號嫌疑

新 bug 最大的來源是上一輪的「修正」本身。

- 固定派一個 agent **專責對抗性拆解上一個 commit 的 diff**，任務寫成「假設它改壞了，去證明它」，並要求**逐檔完整讀改動後的檔案**（不是只讀 diff）。
- 三種固定型：
  - **(a) 修 A 引發鄰居 B** — 元素改成按鈕後 sr-only 文字混進外層 `data-i18n` 容器的 textContent 快取；toggle 修反轉後呼叫端自讀 computed display，與新結局脫鉤。
  - **(b) 改一邊沒回頭查兄弟工件** — 同頁其他區塊、跨頁同一份資料的另一步、宣稱對齊的正本。對抗拆解時把「**這個修正的兄弟是誰**」當固定問題問。
  - **(c) 引正本沒真的開正本** — 註解宣稱某個名字對齊某處，實際那個名字不存在。
- 修東西最容易犯的兩個機械錯：改名／重構**漏掉一處引用**；用 `sed`／`String.replace` 做**只換第一個出現處**的替換（跨行註解被切斷、cache-busting 從來沒生效都是這樣來的）。兩者靜態掃描都看不到，要靠 runtime 或 `dist/` 產物驗證。

## 每條發現自己驗過再動手

- subagent 讀得多、記得糊，會把「應該是這樣」寫成「就是這樣」。**動手前自己 grep／算一次／在瀏覽器裡跑一次。** 對比度尤其要自己算，不要抄報告裡的數字。
- **駁回的也要寫進 commit message 附理由**，否則下一輪的 agent 會再提一次同一條。
- **本專案自己的註解／commit message／README 不算證據。** 任何形如「這裡是這樣寫的／這裡沒有這個」的斷言，證據只能是**實際檔案本身**（貼出 grep 結果或行號）。註解記錄的是寫它當下的推測，把它當證據等於把自己的結論當前提；更糟的是會讓你**駁回正確的外部發現**，對抗性審查的價值正好被抵銷。查證後發現舊註解是錯的，順手改掉。
- 腳本吐出**全體皆違規**這種結果時，先懷疑腳本、不要懷疑專案。

## 迴圈到零，中途不問

- 一輪 = **完整扇出 → 驗證每個發現 → 修 → 視覺指紋比對上一個 commit → `npm run check` → 提交推送 → 立刻開下一輪**（把上一輪的修正列為頭號嫌疑）。
- 收斂條件是客觀的：**那一輪的完整扇出零實質發現**。不是使用者的許可。**不要停下來問「要不要再跑一輪」**——答案永遠是「要」。
- 判準是「這一輪在專案程式碼裡找不到違規」，不是「這一輪什麼都沒改」——測試／文件的補強會一直有邊際收益。
- 只有當某一輪的每一個 agent 都回報零實質違規時才停，並在最後報告收斂數據。
